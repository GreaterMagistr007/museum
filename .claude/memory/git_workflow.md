В этом проекте работаем напрямую в `master`, без фичевых веток и без TASK-ID в коммитах.

**Why:** В проекте нет внешнего трекера задач, поэтому глобальное правило `TASK-ID: message` неприменимо. Деплой (`server/deploy.sh`) разворачивает код только из ветки `master` через `git archive master server/`, поэтому любые изменения должны быть именно в `master`, иначе они просто не попадут на прод.

**How to apply:**
- Все коммиты — в `master`. Не создавать фичевые ветки и не предлагать MR/PR.
- Сообщения коммитов — короткие, без префикса задачи. Допустимо: русский (`сжатие картинок перед отправкой на сервер`) или conventional-style (`feat: ...`, `fix: ...`, `chore: ...`).
- При обнаружении незакоммиченных правок не уточнять про TASK-ID, а сразу формулировать сообщение по сути изменений.
- Co-Authored-By не добавлять (общее правило).
